# 上下文压缩协议

## 这是什么

原力OS 的会话记忆衰减协议。当对话变长时，早期的治理决策、六判断结果、gate 输出会被挤出上下文窗口，导致后续执行偏离原始决策。

本协议定义：什么必须保留、什么可以压缩、什么可以删除、何时触发压缩、压缩后的标准格式。

## 为什么需要

原力OS 的核心价值在于 `六判断 → 主题层 → 策略层 → 执行层` 的治理链条完整性。如果六判断结果在第 20 轮对话时已经被挤出窗口，执行层就失去了治理锚点，变成无根执行。

压缩不是为了省空间，而是为了在有限窗口内保持治理链条的完整投射。

## 何时使用

- 对话超过 15 轮
- 任务从一个阶段切换到另一个阶段（探索 → 规划 → 执行）
- agent 感知到早期决策开始模糊
- 上下文窗口占用率超过 60%

---

## 1. 信息衰减优先级

四层衰减，从永不压缩到可删除。

### Layer 0: 锚点层（永不压缩）

这些信息一旦丢失，整个治理链条断裂。无论上下文多紧张，都必须原样保留。

| 信息类型 | 为什么永不压缩 |
|---|---|
| 六判断结果 | 治理OS的根判断，所有后续决策的合法性来源 |
| 任务族判断 + mode 判断 | 决定了 artifact pack 结构和执行深度 |
| 主题层 gate 的结论 | "为什么进入"——丢失后任务失去方向锚 |
| 策略层 gate 的核心矛盾和选定路线 | "怎么赢"——丢失后执行变成无策略搬砖 |
| 当前最大失真 | 失真是治理的校准器，丢失后系统失去自纠能力 |
| 验真目标（done condition） | 没有 done condition 就无法判断完成 |

### Layer 1: 决策层（按需压缩）

保留结论和关键证据，压缩完整推理过程。

| 信息类型 | 压缩方式 |
|---|---|
| 策略层完整分析过程 | 压缩为：结论 + 支撑该结论的 1-2 条关键证据 |
| 执行路由的选择理由 | 压缩为：选了什么 skill/chain、为什么选它（一句话） |
| 中间验真结果 | 保留通过/未通过 + 原因，删除验真过程细节 |
| skill-router 的路由决策 | 保留最终路径，删除候选比较过程 |
| 3x3 矩阵的逐格分析 | 压缩为不通过的格子 + 原因（通过的格子删除分析） |

### Layer 2: 过程层（可安全压缩）

压缩为一句话摘要，保留"做了什么、发现了什么"。

| 信息类型 | 压缩方式 |
|---|---|
| 探索阶段的文件读取 | "读了 X 文件，发现 Y" |
| 工具调用的详细输出 | "调用 X 工具，结果是 Y" |
| 搜索和定位过程 | "搜索了 X，找到了 Y" |
| 多轮确认对话 | 压缩为最终确认的结论 |
| 中间草稿和迭代 | 只保留最终版本 |

### Layer 3: 噪声层（可删除）

直接删除，不保留摘要。

| 信息类型 | 为什么可以删除 |
|---|---|
| 工具的原始 JSON 输出 | 结果已在 Layer 2 摘要中体现 |
| 重复的文件内容读取 | 同一文件的多次读取只保留最后一次的摘要 |
| 系统提醒和环境信息 | 不影响任务决策 |
| 对话中的寒暄、感谢、确认语 | 零信息量 |
| 已被后续决策覆盖的早期假设 | 被推翻的假设不需要保留 |

## 2. 压缩触发时机

### 主动触发

| 触发条件 | 动作 |
|---|---|
| 对话轮次 >= 15 | 执行一次完整压缩 |
| 上下文占用率 > 60%（估算） | 执行一次完整压缩 |
| 任务阶段切换（探索 → 规划、规划 → 执行、执行 → 验真） | 将上一阶段压缩为摘要 |
| agent 发现自己在重复询问已回答过的问题 | 立即压缩，这是信息丢失的信号 |

### 阶段性压缩节奏

```
六判断完成后 → 锁定锚点层，不再修改
主题层 gate 完成后 → 锁定主题结论，压缩主题分析过程
策略层 gate 完成后 → 锁定策略结论，压缩策略分析过程
执行层每完成一个子任务 → 更新执行进度，压缩已完成子任务的过程细节
验真完成后 → 锁定验真结论，压缩验真过程
```

### 不触发压缩的情况

- 对话轮次 < 10 且上下文充裕
- 当前正在进行高密度决策（策略层分析中），此时压缩可能丢失正在使用的推理链
- 用户明确要求保留完整历史

## 3. 压缩锚点格式

当压缩触发时，agent 应在内部将之前的会话内容替换为以下格式。这个格式是压缩后的"会话快照"。

```markdown
## 原力OS 会话压缩锚点

### 治理锚点（永不压缩）
- 六判断:
  - 自治判断: [结果]
  - 全局最优判断: [结果]
  - 能力复用判断: [结果]
  - 验真判断: [结果]
  - 进化判断: [结果]
  - 当前最大失真: [一句话]
- 任务族: [族名] | mode: [full/light]
- 主题层结论: [为什么进入，一句话]
- 策略层结论: [核心矛盾] → [选定路线]
- 验真目标: [done condition]

### 决策摘要（压缩保留）
- [决策1]: [结论] <- [关键证据]
- [决策2]: [结论] <- [关键证据]
- ...

### 执行进度
- 已完成: [列表，每项一句话]
- 进行中: [当前子任务 + 当前状态]
- 待执行: [列表]

### 已捕获的进化点
- [进化点1]
- [进化点2]

### 压缩元信息
- 压缩时间: [轮次/阶段]
- 压缩前轮次: [N]
- 被压缩的主要内容: [概述]
```

### 格式使用规则

1. **治理锚点**：从 Layer 0 原样复制，一字不改
2. **决策摘要**：从 Layer 1 提取，每条决策不超过两行
3. **执行进度**：实时更新，反映当前真实状态
4. **进化点**：只记录确认有复用价值的，不记录"可能有用"的
5. **压缩元信息**：让后续 agent（包括自己）知道压缩了什么

## 4. 与现有机制的集成

### 与 3x3 矩阵的关系

3x3 矩阵（治理OS 三条线 x 工作OS 三层）在每层 gate 时使用。压缩协议不改变矩阵的运行方式，只决定矩阵输出的保留策略：

- 矩阵中"不通过"的格子：保留在决策摘要中（Layer 1）
- 矩阵中"通过"的格子：压缩时可删除分析过程
- 矩阵的整体结论：保留在治理锚点中（Layer 0）

### 与 evidence-gate 的关系

evidence-gate 负责验真。压缩协议确保 evidence-gate 所需的信息不被压缩掉：

- 验真目标（done condition）在 Layer 0，永不压缩
- 验真所需的关键证据在 Layer 1，压缩保留
- evidence-gate 的验真过程本身在 Layer 2，可压缩为结论

当 evidence-gate 运行时，如果发现所需信息已被压缩，应从压缩锚点中恢复，而非要求用户重新提供。

### 与 closure-evolution 的关系

closure-evolution 在任务结束时运行，需要回顾整个任务过程提取进化点。压缩协议通过"已捕获的进化点"字段实时积累进化候选，使得 closure-evolution 不依赖完整历史：

- 每次压缩时，将已识别的进化点写入锚点
- closure-evolution 从锚点的进化点列表出发，而非从完整历史中挖掘
- 这让 closure-evolution 在长会话中也能高质量运行

### 与 skill-router 的关系

skill-router 在执行层选择路径。压缩协议确保 skill-router 的决策背景不丢失：

- 路由选择结果在 Layer 1，压缩保留
- 路由选择的候选比较过程在 Layer 2，可压缩
- 如果任务中途需要重新路由，压缩锚点中的策略层结论提供足够的上下文

## 5. 治理线检查

对本协议自身过三条治理线。

### 递归进化

**问：这个协议是否让每次长会话都更稳？**

是。每次长会话的治理决策不再因为上下文溢出而悄悄丢失。压缩锚点格式是标准化的，意味着：
- agent 可以从任意压缩点恢复治理链条
- 长会话的后半段不再"忘记"前半段的决策
- 压缩本身也是一次"治理决策还活着吗"的强制检查

**风险**：如果压缩触发过于频繁，会消耗算力在格式化上而非实际推进。因此设置了 15 轮 / 60% 的最低阈值。

### 全局最优

**问：这个协议是否真的解决了上下文丢失问题，而不只是增加了格式负担？**

协议解决的核心问题是：治理锚点（六判断、gate 结论）在长会话中不可丢失。这是结构性问题，不是格式问题。

**自检**：
- 压缩锚点格式约 15-20 行，占上下文 < 1%，格式负担极低
- 如果不压缩，相同信息散布在几十轮对话中，反而占用更多上下文
- 压缩后的格式可被 evidence-gate 和 closure-evolution 直接消费，减少了这些机制的搜索成本

**风险**：如果 Layer 1（决策层）的压缩过于激进，可能丢失关键证据。因此要求保留"结论 + 关键证据"而非只保留结论。

### 人类友好

**问：这个协议是否减少了人类重复说明上下文的负担？**

是。最常见的人类痛点是："我之前说过了，你怎么又问？"这通常发生在：
- 六判断结果被挤出窗口
- 策略选择被遗忘
- done condition 消失

压缩锚点将这些信息固定在标准位置，agent 在任何时候都可以回溯，不需要人类重复。

**额外收益**：压缩锚点格式对人类也是可读的。如果人类想回顾当前任务状态，看一眼锚点即可，不需要翻阅全部对话历史。

## 6. 实施指南

### 对 agent 的要求

1. 在对话达到触发条件时，主动执行压缩，不需要人类指令
2. 压缩时显式告知人类："会话已压缩，治理锚点已锁定"
3. 压缩后的第一次回复中，简要复述当前锚点状态，确认与人类的理解一致
4. 如果压缩过程中发现治理锚点缺失（六判断没做、gate 没过），标记为失真而非补造

### 对 SKILL.md 的引用方式

在 `os-yuanli/SKILL.md` 的 References 中添加本文件。在 Workflow 的任意阶段，当对话变长时，agent 应参考本协议执行压缩。

### 渐进式采用

本协议不要求一次性改造所有机制。推荐的采用顺序：

1. 先在 `os-yuanli` 的 full mode 长会话中试用
2. 验证锚点格式是否足够支撑 evidence-gate 和 closure-evolution
3. 根据实际使用反馈调整 Layer 1 的压缩粒度
4. 考虑是否需要将压缩锚点持久化到文件（而非只在上下文中）
